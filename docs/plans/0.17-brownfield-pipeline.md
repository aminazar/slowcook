# 0.17 — Brownfield pipeline: refine becomes the leverage point

## Trigger

PR #147 (rewo story-017 plate brew) hit MOCKUP_DESIGN_CONFLICT after $1.82 because vibe + testgen diverged on component naming. Tactical hand-fixes (cli α.27→α.30) closed gaps but didn't address the root cause: refine doesn't surface enough brownfield context for downstream agents to converge.

A 7-agent hand-simulation on /me/bookmarks (rewo `mock-perfect/.pipeline-bookmarks/`) traced every divergence/stuck point back to refine missing input.

## Principle

**Fix refine first. Every downstream agent's failure mode is "input shape, not agent logic."**

Per-agent input/output table (the spec for this release line):

| Agent | Critical inputs | Critical outputs | Failure if input missing |
|---|---|---|---|
| refine | issue + existing tests + migrations + components + test helpers | spec.yaml + history-index.json | downstream cascade |
| vibe | spec + perfect mock + history-index | mock changes (extends) | duplicate components, wrong names |
| testgen | spec + existing components + tests + helpers | new tests OR modify existing | invented prop names + invented mocking idioms |
| recon | mock + tests + ownership grep | renaming-map + applied diffs | breaks other stories' tests |
| brew | spec + mock + tests + migrations + handlers | data layer + new handlers + (rare) migrations | duplicate migrations + rewriting handlers |
| refactor | full codebase + this story's diff | cost/benefit-per-proposal + applied diffs | applies-everything; misses cross-story patterns |

## Release sequence

### 0.17.0 — Refine becomes history-aware

**Scope**: refine reads more inputs + emits a structured history index.

New refine inputs:
- `tests/integration/**` — existing test files + their imports
- `supabase/migrations/**` — existing schema
- `src/components/**` — existing component files + their default-export prop signatures
- `src/app/api/**/route.ts` — existing API handlers + their methods
- `tests/helpers/**` — existing test helper files

New refine output: `.brewing/history-index.json`

```json
{
  "components": [
    { "name": "MemberReactionsPage", "file": "src/components/members/MemberReactionsPage.tsx",
      "props": ["owner", "viewer", "reactions?", "followsAvailable?", "initiallyFollowing?"],
      "tests_covering": ["story-005-ui.test.tsx", "story-011-page.test.ts"] }
  ],
  "migrations": [
    { "file": "supabase/migrations/00018_story_007_bookmarks.sql",
      "tables": ["bookmarks"],
      "columns": { "bookmarks": ["id", "member_id", "rewo_id", "saved_at"] } }
  ],
  "api_routes": [
    { "method": "POST", "path": "/api/bookmarks", "file": "src/app/api/bookmarks/route.ts" },
    { "method": "GET",  "path": "/api/bookmarks", "file": "src/app/api/bookmarks/route.ts" }
  ],
  "test_helpers": [
    { "name": "mockFetch", "file": "tests/helpers/mocks/fetch.ts", "purpose": "mock fetch for API tests" },
    { "name": "renderWithProviders", "file": "tests/helpers/render.tsx", "purpose": "wrap component with context providers" }
  ]
}
```

New refine prompt section: "**Brownfield-conflict Q&A**" — refine asks PM-targeted questions about story-history conflicts BEFORE finalizing spec:
- "Component X already exists with prop shape Y; new spec uses Z. Extend (back-compat) or replace (breaks story-N)?"
- "Migration table Y already exists; new spec implies columns A+B not in Y. Add migration?"
- "Test helper Z already exists for this idiom; use it or replace?"

Files:
- `packages/cli/src/commands/refine/index.ts` — call new history-index emitter before spec emission
- `packages/cli/src/commands/refine/history-index.ts` — NEW
- `packages/llm-anthropic/src/prompts/refine.ts` — append history-aware section + brownfield Q&A

### 0.17.1 — Testgen reads existing prod + tests

**Scope**: testgen consumes history-index. Can MODIFY existing tests instead of inventing new ones.

Testgen prompt change:
- "Read history-index.json. For every component your test will reference, use its EXISTING name + EXISTING prop signature from history-index.components."
- "If history-index.components shows tests already cover the surface you're about to test, default to MODIFYING those tests (add new assertions). Only create a NEW test file if the surface is genuinely net-new."
- "Read tests/helpers/ via history-index.test_helpers and use those mocking idioms."

Files:
- `packages/cli/src/commands/testgen/agent.ts` — pass history-index into testgen prompt
- `packages/llm-anthropic/src/prompts/testgen.ts` — new prompt section

### 0.17.2 — Vibe reads perfect-mock + extends existing files

**Scope**: vibe receives the perfect-mock as starting state (where it exists) + history-index.

Vibe prompt change:
- "The mock app at `mock/` is the design contract. Existing component files exist there because they exist in prod. Your default action is EXTEND THE EXISTING FILE, not create a new one."
- "If the spec implies a NEW component (no analog in mock/ or src/), create it with a name that matches the spec's natural terms — vague names like 'XWithFeature' are anti-patterns."

Files:
- `packages/cli/src/commands/vibe/index.ts` — pass mock + history-index into vibe prompt
- `packages/llm-anthropic/src/prompts/vibe.ts` — new prompt section

### 0.17.4 — Recon as a brew pre-step (narrow)

**Scope**: with refine + history-aware vibe/testgen, recon's job shrinks dramatically. It becomes a final mechanical safety net.

Recon checks:
- (a) every test import → file exists in mock + src/
- (b) every test prop usage → matches mock's component signature
- (c) every test assertion → has a matching affordance in mock
- (d) brownfield grep: rename-safety check before applying any rename

Output: `recon-result.json` with renaming-map + escalation-on-conflict (MOCKUP_DESIGN_CONFLICT or VIBE_RECIPE_NAME_DRIFT).

Files:
- `packages/cli/src/commands/recon/` — NEW command
- Wire into `slowcook-brew-auto.yml` template as pre-brew step

### 0.17.5 — Brew existence checks + migration suggestions

**Scope**: brew's first action becomes a "what already exists?" pass before any write.

Brew prompt change:
- "Before writing ANY new file: read history-index.{api_routes, migrations, components}. If a route/migration/component for your target already exists, your default is to EDIT IT, not write a new one."
- "If a migration is needed AND no existing migration covers the columns you need: emit a NEW migration file with a sequential number. Document WHY in a top-of-file comment."

Files:
- `packages/cli/src/commands/brew/agent.ts` — read history-index in, log "found existing X at Y" before tool calls
- `packages/llm-anthropic/src/prompts/brew.ts` — new pre-write check section

### 0.17.6 — Refactor with cost/benefit per proposal

**Scope**: refactor receives whole codebase as scope (not just diff). Outputs explicit accept/reject/defer per proposal.

Refactor prompt:
- "List proposals as { id, title, why, files_touched, estimated_LOC_change, risk: low|med|high, recommendation: apply|defer|reject }."
- "Apply only proposals you marked `apply` AND with risk=low. Everything else: write to `.brewing/refactor-proposals.md` for human review."
- "Look for cross-story patterns (e.g., 2 toggles with the same shape → propose useOptimisticToggle). Don't extract on first sight; extract on third."

Files:
- `packages/cli/src/commands/refactor/` — likely NEW command (verify exists)
- `packages/llm-anthropic/src/prompts/refactor.ts` — NEW

## 0.18.0 — Mocking agent (perfect-mock generator)

**Scope**: `slowcook init --from-prod` walks src/, generates mock/ with the 4-strategy taxonomy.

Components:
- Strategy detector: classifies each prod file (A/B/C2/D)
- Bulk-copy + transform: applies the picked strategy
- Per-table fixture generator: walks supabase/migrations/, emits fixture skeletons
- Server-mock layer: shipped as `@slowcook-ai/mock-supabase` package, consumer extends with table dispatch

Inputs the agent needs (from rewo perfect-mock build, see project memory `project_perfect_mock_taxonomy.md`):
- src/ tree, package.json, tsconfig, tailwind, next.config, supabase/migrations, tests/, docs/

Files:
- `packages/cli/src/commands/init/from-prod.ts` — NEW
- `packages/mock-supabase/` — NEW package (the fluent fixture-backed Supabase client)
- `packages/llm-anthropic/src/prompts/mock-from-prod.ts` — NEW

## What's NOT in this plan

- Static prerender for mock — explicitly NOT a goal; mock is dev-only
- Mock having full prod parity for every Supabase method — only the SUBSET prod actually uses; new methods get added incrementally
- Mocking websockets / server actions — Strategy D (skip + annotate); revisit when a consumer needs it
