## #1 — `slowcook recipe --backend` mode (DECIDED 2026-06-01)

### Problem

Local-claude-pipeline session-batch 5 finding #151 #1: testgen currently has no backend-handler-aware mode. When the consumer is a NestJS-CQRS backend (delgoosh), testgen's defaults emit React Testing Library scaffolding that doesn't match. Author of finding #1 hand-built handler-test conventions (one `*.helper.test.ts` per handler, `@slowcook-stub` line-1 markers, TestManager beforeAll/beforeEach/afterAll, per-test inlined seed helpers) and asked for `slowcook recipe --backend` to ship them as a first-class mode.

### Options considered

- **A** — single backend mode hardcoded to NestJS-CQRS in `@slowcook-ai/cli` directly
- **B1** — `slowcook recipe --backend` flag + stack-detection-driven adapter selection, single package with first-party adapters in-tree (e.g. `recipe/backend/nestjs.ts`, `recipe/backend/express.ts`)
- **B2** — adapter contract package + first-party adapter packages mirroring the existing `stack-ts` / `forge-github` layout

### Chosen: **B2**

- `@slowcook-ai/backend-adapter` — interface-only package (~100 LoC). Exports `BackendAdapter` interface: `detect(packageJson): boolean`, `emitHandlerTestScaffold(handler): EmittedFile[]`, `seedHelperFor(handler): string`, etc.
- `@slowcook-ai/backend-adapter-nestjs` — first impl. Captures the patterns documented in `docs/testgen-backend-conventions.md` (shipped PR #158). NestJS-CQRS one-helper-per-handler pattern; per-test inlined seed; `@slowcook-stub: <HandlerName>` throws.
- `slowcook recipe --backend` flag in cli — reads consumer's `package.json`, calls `detect()` on each loaded adapter, picks the matching one. Fail-loud if multiple match or none match.
- `@slowcook-ai/backend-adapter-express` — follow-up package after NestJS adapter is dogfooded.
- Community can ship their own adapters (`@yourorg/slowcook-backend-adapter-fastify` etc.).

### Rationale

Symmetric to the existing `@slowcook-ai/stack-ts` + `@slowcook-ai/forge-github` pattern — keeps the cli's adapter-loading code uniform. The contract package becomes a public stability commitment, which is the cost of admitting community contributions, but that's already the open-contributors direction (decision #4 in 0.20-decisions.md).

A is rejected because it ties the cli to one framework forever; B1 is rejected because in-tree adapters give the cli unbounded growth + force every adapter author to PR against cli.

### Scope estimate

- 0.5d — `backend-adapter` interface package + tests
- 1.5d — `backend-adapter-nestjs` impl + dogfood on delgoosh
- 0.5d — cli flag wiring + adapter selection
- 0.5d — `backend-adapter-express` follow-up

**~3d total.** First two land in 0.20, Express adapter could slip to 0.21.

## #2 — `slowcook mirror` codegen (DECIDED 2026-06-01)

### Problem

Local-claude-pipeline session-batch 5 finding #151 #7: delgoosh story-017 (TherapistChatPage) was a strict role-mirror of story-006 (PatientChatPage). The agent ended up with ~80% duplicate body. Differences were:

1. **Path segments** — `apps/patient/...` → `apps/therapist/...`
2. **Identifier prefixes** — `PatientChatPage` → `TherapistChatPage`
3. **Role-perspective inversion** — sender becomes counterparty
4. **DTO rename mid-flight** — `unreadCountForPatient` → `unreadCountForViewer` to make the field role-agnostic

The agent asked for `slowcook mirror --source-story 006 --target-role therapist` — deterministic emission, no LLM, no drift.

### Options considered

- **A** — pure template codegen with explicit substitution map at invocation time
- **B** — spec-level `mirror_of` + `mirror_substitutions` metadata, brew picks it up + emits substituted starting commit
- **C** — sigil markers in source story (`<!-- @mirror-substitute role -->`), `slowcook mirror` walks source + swaps at marked sites
- **D** — parametrize-at-source-write + minimal mirror CLI command

### Chosen: **D**

The agent's mid-flight DTO rename (`unreadCountForPatient` → `unreadCountForViewer`) is the actual signal: the right fix is to refactor source stories to be role-agnostic at write time, then the mirror reduces to a trivial path + identifier swap.

Concrete 0.20 scope:

1. **Refine prompt addendum** — when a story declares `related_specs[].relationship: mirror`, refine proposes role-agnostic parametrization at spec-edit time (DTO field naming, component-factory shape, hook signature).
2. **Brew prompt addendum** — already partially shipped in PR #159. Tighten: when implementing a `mirror of X` story, brew should actively refactor toward role-agnostic where it sees the chance (not just "extract shared component").
3. **`slowcook mirror --from <story> --as <role>`** — small CLI utility (~30 LoC). Instantiates the source story's files with the target role. Substitutes path segments (`/patient/` → `/therapist/`) + identifier prefixes (`Patient` → `Therapist`); everything else is verbatim copy.

### Rationale

Mirror codegen is a Band-Aid for non-parametric source stories. Determinism the agent asked for falls out of upstream parametrization, not from a textual-substitution command. C is the safer fallback if upstream parametrization doesn't take; we'll ship D first and reach for C if mirror drift recurs.

Known pushback: option D assumes refine + brew actively push parametrization at write time. If they don't, `slowcook mirror` emits broken mirrors (because the source has hardcoded role names) and we're back at LLM-mediated mirror — effectively option B without the spec metadata. The mitigation is the refine + brew prompt addendums above; if those don't take after two empirical dogfoods, fall back to C.

### Scope estimate

- 0.25d — refine prompt addendum + eval fixture
- 0.25d — brew prompt addendum (extends #159's work)
- 0.5d — `slowcook mirror` CLI command + tests
- 0.5d — dogfood on delgoosh next mirror story (no story queued yet)

**~1.5d total.** Lands in 0.20.
