# 0.7.17 — Pipeline-gap static assertions (page-link + schema)

> Status: drafted 2026-04-23. Implementation not started.
>
> Parent roadmap: [`roadmap-0.7-to-0.11.md`](./roadmap-0.7-to-0.11.md).
> Related memories: `project_page_integration_gap_in_tier1.md`, `project_migration_gap_in_pipeline.md`.

## Goal

Close two recurring gaps where the pipeline ships green but the feature is invisible to the user:

1. **Page-integration gap** — tier-1 component tests pass, but the page that should mount the component either never imports it (story-006 / rewo PR #62 hand-patch) or does not exist at all (story-005 `/u/<handle>` page — hand-patch pending as of 2026-04-23).
2. **Migration gap** — handler tests mock the DB, but `supabase/migrations/` never receives the DDL the spec invariants describe (story-005's `handle` column, story-006's `handle_confirmed` / `handle_changed_at` — both manually written 2026-04-23).

Both gaps have the same shape: **spec names a runtime artefact that no pipeline stage has a lane to produce**. The 0.8 tier-2 acceptance effort catches both for free (a real browser + a real Postgres), but it's weeks out. This doc specifies the static-analysis interim that fills the gap at tier-1.

Also bundles the small `slowcook-testgen.yml` workflow input divergence that rewo took on 2026-04-23 (the workflow grew an optional `spec` input; this release upstreams it into the forge-github template).

## Scope — three tasks

### 1. Testgen emits a page-link static test

When a spec's `ui_behavior` names a route (`/profile`, `/u/<handle>`, `/feed/personal`, etc.) AND the story produces or references a named component, testgen emits one additional file at `tests/integration/story-N-page.test.ts`:

```ts
import { readFileSync, existsSync } from "fs";

it("story-006 /profile page imports ProfileEditForm", () => {
  const path = "src/app/(main)/profile/page.tsx";
  expect(existsSync(path)).toBe(true);
  const src = readFileSync(path, "utf8");
  expect(src).toMatch(
    /import\s+\{[^}]*\bProfileEditForm\b[^}]*\}\s+from\s+["']@\/components\/profile\/ProfileEditForm["']/
  );
  expect(src).toMatch(/<\s*ProfileEditForm\b/);
});
```

Two assertions — import AND JSX usage — because an unused import is the failure mode next to "no import at all." Both are cheap regex checks; no runtime.

**How testgen decides when to emit:**
- Spec's `ui_behavior.*` mentions a specific path (`/profile`, `/u/...`, etc.) — regex scan `/\/[a-z][a-z0-9\/-]*/i` in the ui_behavior blocks.
- Spec or testgen output names a component file under `src/components/**`.
- Map route → expected page file using Next.js App Router conventions (route `/foo` ⇒ `src/app/(main)/foo/page.tsx` OR `src/app/foo/page.tsx` — testgen tries both, the assertion uses the one that exists OR creates a stub for the first).

**Brew's allowed-paths:** already covers `src/app/**/*.tsx` as of 0.7.5, so brew can close this by editing the page. No brew change needed.

### 2. Testgen emits a schema-assertion test

When any of a spec's `invariants` match `/migration adds|alter table|add column|create table/i`, testgen emits `tests/schema/story-N.test.ts`:

```ts
import { readdirSync, readFileSync } from "fs";

it("story-006 migrations add handle_confirmed + handle_changed_at", () => {
  const all = readdirSync("supabase/migrations")
    .filter(f => f.endsWith(".sql"))
    .map(f => readFileSync(`supabase/migrations/${f}`, "utf8"))
    .join("\n");
  expect(all).toMatch(/\balter\s+table\s+(public\.)?profiles\b[\s\S]*?\bhandle_confirmed\b/i);
  expect(all).toMatch(/\balter\s+table\s+(public\.)?profiles\b[\s\S]*?\bhandle_changed_at\b/i);
});
```

Column names come from the invariant text via `/\b(?:add\s+column|adds?)\s+[\w.]*?\.?(\w+)\s+(boolean|text|int|timestamp|uuid|numeric)\b/gi` — shallow but sufficient for the shape the specs already use.

**Brew's allowed-paths:** extend to `supabase/migrations/**/*.sql` (new). Brew may need spec-specific prompt context ("the spec invariants describe DDL; write a new migration file numbered after the highest existing one").

**Risk:** brew currently has zero plpgsql experience in its prompt. First dogfood run will tell us whether the agent can write DDL cleanly. Fallback: brew writes a placeholder + halt, operator finishes by hand. Acceptable for the first revolution.

### 2a. Drive-by: `--spec` input normalisation (5-minute fix)

`slowcook testgen --spec story-005` silently no-ops today: the CLI treats the whole string as the story id, `readSpec(root, "story-005")` looks for `specs/story-story-005.yaml` which doesn't exist, the spec is silently skipped, and `targets` ends up empty → `"Noop: no active specs without tests."`

Tripped on the 2026-04-23 story-005 dogfood run. Fix: strip a leading `story-` prefix before passing to `readSpec` / `handlerTestPathFor`. Emit a WARNING when the normalisation kicks in so the operator knows what happened, and THROW (not skip) when the id has no matching spec after normalisation — silent no-op is the actual bug.

```ts
function normalizeSpecId(raw: string): string {
  return raw.replace(/^story-/, "");
}
```

One-line change in `packages/cli/src/commands/testgen/index.ts` where `args.specId` gets parsed. Test with `vitest` unit test in `packages/cli/src/commands/testgen/index.test.ts`.

### 3. Upstream the `slowcook-testgen.yml` `spec` input

Rewo diverged on 2026-04-23 to accept `workflow_dispatch.inputs.spec` (empty = `--all`, set = `--spec <id>`). Bring it back into the template in `packages/forge-github/src/templates.ts` so future `slowcook init` runs get parity. Rewo's workflow then reconverges on re-init.

## Out of scope for 0.7.17

- Tier-2 acceptance tests — 0.8.
- Config/env-var gap (some specs require new env keys) — same class of gap, next candidate if we see it twice.
- Edge-function / storage-bucket provisioning — separate track; see Supabase ops doc.
- Deeper DDL validation (column TYPE, NOT NULL, default value) — the regex shape is already noisy enough; tighten when the LLM starts producing wrong-shape columns.

## Validation

Dogfood sequence that proves the release:

1. Revert rewo's manual migrations 00016/00017 on a scratch branch.
2. Re-run testgen story-006 on that branch with 0.7.17 CLI; assert `story-006-page.test.ts` + `story-006-schema.test.ts` get emitted.
3. Re-run brew with the expanded allowed-paths; assert it writes the migration file AND page-import in the same iteration (or halts gracefully if it can't).
4. Story-005 path: after tier-1 UI tests emit (via the current story-005 dogfood run), 0.7.17 should ALSO emit `story-005-page.test.ts` that asserts `/u/[handle]/page.tsx` exists and imports whatever component story-005's bundle introduces.

If (4) goes clean, the claim "pipeline catches its own integration gaps" finally holds.

## Cost estimate

Per-story incremental tokens for testgen: +500-1000 output tokens for the two new test files combined. At Sonnet pricing that's ~$0.015 per story. Negligible.

Brew cost if it has to write migrations: unknown — first datapoint. Budget 1.5× the handler-test iteration cost as a rough upper bound.
