# 0.8 — LLM adapter refactor (package extraction, no behaviour change)

> Status: drafted 2026-04-23. Implementation not started.
>
> Parent roadmap: [`roadmap-0.7-to-0.11.md`](./roadmap-0.7-to-0.11.md) — tier-2 acceptance work (previously 0.8 in that doc) moves to 0.9 after this refactor lands.

## Goal

Extract the Anthropic-specific LLM surface out of `@slowcook-ai/cli` into a dedicated `@slowcook-ai/llm-anthropic` package, with the generic `LlmClient` interface living in `@slowcook-ai/core`. CLI imports the interface from core + the default Anthropic adapter from llm-anthropic, wired identically to today. **No behavioural change; no model-choice change; no consumer-visible change.**

This is the smallest step that makes "point slowcook at a different LLM" a package-boundary swap rather than a source edit. Not "implement a second provider" — that's 0.9+ scope. The asked-for unit here is **decoupling**.

User's framing (2026-04-23): *"of course I am not asking for IMPLEMENTATION for other llm models, I am asking for ABSTRACTION that enables DECOUPLING..."*

## What's in the current code today

- **`packages/cli/src/commands/refine/llm.ts`** — defines the `LlmClient` interface, `AnthropicClient` class implementing it, the `PRICING_PER_M_TOKENS` table, `costUsdForUsage`, `costMarker` / `parseCostMarkers` helpers.
- **Refine + testgen** import and use `LlmClient` through its shared interface — clean boundary already.
- **Brew** imports `@anthropic-ai/sdk` directly for its tool-use surface (`Anthropic.Messages.Tool`, `ToolUseBlock`, `ToolResultBlockParam`, `TextBlock`, cache_control, etc.). That surface is Anthropic-specific and NOT a clean fit for a provider-agnostic interface yet.

## Scope — five changes

### 1. New package `@slowcook-ai/llm-anthropic`

Fresh workspace package at `packages/llm-anthropic/`. Exports:

```ts
// index.ts
export { AnthropicClient } from "./client.js";
export { costUsdForUsage, costMarker, parseCostMarkers, PRICING_PER_M_TOKENS } from "./pricing.js";
```

`package.json` minimal: depends on `@slowcook-ai/core` (for the interface) + `@anthropic-ai/sdk`. `prepublishOnly: "tsc -b"` per the build-before-publish rule.

### 2. Move `LlmClient` interface + types to `@slowcook-ai/core`

`packages/core/src/llm.ts` gets:

```ts
export interface LlmClient {
  complete(args: LlmRequest): Promise<LlmResponse>;
}
export interface LlmMessage { role: "user" | "assistant"; content: string; }
export interface LlmRequest { /* ... same as today */ }
export interface LlmUsage { /* ... */ }
export interface LlmResponse { /* ... */ }
```

Core re-exports these through its barrel. Core remains zero-dep — it defines SHAPES, not implementations. Everyone depending on core gets the interface without dragging in the Anthropic SDK.

### 3. Move pricing + cost helpers to llm-anthropic

`PRICING_PER_M_TOKENS`, `costUsdForUsage`, `costMarker`, `parseCostMarkers` all live in `packages/llm-anthropic/src/pricing.ts`. The reasoning: pricing is provider-specific (Anthropic's cache-read-10%/cache-create-125% bill math doesn't generalize); cost markers mention `model=claude-...` strings. Keeping them next to the Anthropic adapter is honest.

Edge: refine + testgen + brew + on-brew-merged all call `costUsdForUsage` or emit cost markers. They'll now import from `@slowcook-ai/llm-anthropic` instead of `../refine/llm.js`. That's the point — the callers surface their Anthropic-specific dependency at the import site.

### 4. CLI `refine/llm.ts` becomes a thin default-adapter selector

The file stays as a call site, not the source of truth:

```ts
// packages/cli/src/commands/refine/llm.ts
import { AnthropicClient } from "@slowcook-ai/llm-anthropic";
export type { LlmClient, LlmRequest, LlmResponse, LlmMessage, LlmUsage } from "@slowcook-ai/core";
export { costUsdForUsage, costMarker, parseCostMarkers } from "@slowcook-ai/llm-anthropic";

/** Today's default adapter — direct Anthropic. Consumers can replace
 * by constructing their own `LlmClient` implementation and passing it
 * where `AnthropicClient` is currently passed in `cli.ts`. */
export { AnthropicClient };
```

All call sites (`cli.ts` + the handful of agent files) keep working unchanged — they import from `./refine/llm.js` the same as today. The refactor is invisible at those sites.

### 5. Brew keeps its direct Anthropic SDK dependency (for now)

Brew's tool-use / tool-result / cache_control surface is Anthropic-specific. A provider-agnostic tool-use interface would be a LARGER design exercise (every provider names these differently: OpenAI `tool_calls`, Anthropic `tool_use_blocks`, etc.). Not part of 0.8. Brew continues to `import Anthropic from "@anthropic-ai/sdk"` directly; documented as a known temporary surface.

When/if a second provider is added, the tool-use abstraction becomes the next layer of refactor. For 0.8 we're honest about the boundary: the SIMPLE `complete()` surface decouples cleanly; the tool-use surface doesn't yet.

## Non-goals

- **No second LLM provider.** Not OpenAI, not local-Ollama, not anything. The goal is the shape that would make that cheap later.
- **No behaviour change.** Refine, testgen, brew all continue to use Claude Opus 4.7 / Sonnet 4.6 defaults exactly as today. Same models, same prompts, same costs.
- **No config file / env-var-based adapter selection.** Consumers who want to swap adapters construct their own instance and pass it. Adding a factory / env-var selector comes when there's a second provider to select.
- **No brew tool-use abstraction.** See §5 above.

## Breaking vs non-breaking

- **Consumer-facing (via `slowcook init` / CLI invocation): zero break.** Same commands, same flags, same env vars. `ANTHROPIC_API_KEY` is still the only LLM env var.
- **SDK-consumer-facing (anyone importing from `@slowcook-ai/cli`): trivial break.** If someone imported `AnthropicClient` from the CLI's deep path (they shouldn't — it's internal), that path changes. The CLI exports its own `cli.ts` surface; internal deep imports are not a public contract. Document the move in CHANGELOG.

## Package publish order

New package `@slowcook-ai/llm-anthropic` must be on npm BEFORE `cli@0.8.0` can resolve it. Sequence:

1. `@slowcook-ai/core@0.8.0` — gains the `LlmClient` interface export. (Bump from 0.7.1; no breaking change, additive.)
2. `@slowcook-ai/llm-anthropic@0.8.0` — new package, first publish.
3. `@slowcook-ai/cli@0.8.0` — depends on both above via `workspace:^`. At publish time resolves to the freshly-published versions.
4. `@slowcook-ai/stack-ts` / `@slowcook-ai/forge-github` — unaffected; no bump needed.

Workspace `prepublishOnly: "tsc -b"` guard on all three ensures fresh `dist/`. Per `feedback_build_before_publish.md` rule.

## Validation

1. **Unit tests move with their code.** `llm.test.ts` moves to `packages/llm-anthropic/src/pricing.test.ts` + `client.test.ts`. Same assertions; same `LlmClient` fake pattern.
2. **CLI test suite** stays green — 157 tests as of 0.7.21 baseline. No count change expected from this refactor; only import-path changes.
3. **Rewo dogfood gate** — bump `.brewing/slowcook-cli-version` to `0.8.0` once published, run a small refine/testgen/brew cycle. Expect identical behaviour (same prompts → same outputs at same costs).
4. **Dry-run second-provider thought experiment** — stub out an `OpenAIClient implements LlmClient` in a throwaway branch, wire it into `cli.ts` via a constant swap. Should type-check + run (failing at actual API call). If it type-checks, the abstraction works. Not committed; just a check on the shape.

## Cost estimate

Pure refactor + test-move work. ~6-8 hours for one engineer (or one agent session).

- 2-3h: move files, update imports, fix build breaks
- 1h: unit-test relocation + re-pass
- 1h: dogfood refine/testgen/brew cycle
- 1-2h: changelog, README, memory updates, commit hygiene, publish sequence

LLM cost for the dogfood cycle: ~$0.50 expected (one simple story through the pipeline).

## What this unlocks

- **Second provider implementations become a feature, not a refactor.** An `@slowcook-ai/llm-openai` package becomes a few hundred lines + a test suite, parallel to what llm-anthropic looks like after 0.8.
- **Fakes in tests can use a real shape.** Test helpers already pass in an `LlmClient` fake; after the move, the fake lives closer to the interface instead of next to the Anthropic client.
- **Pricing becomes per-provider data.** An OpenAI adapter ships its own pricing table; slowcook doesn't need a central pricing registry.
- **Cost markers become readable by non-Anthropic tooling.** `parseCostMarkers` is shared logic; its parsing doesn't assume a model naming convention. Future providers can emit markers with `model=gpt-4o`, and the aggregator treats them uniformly.

## Risk register

- **Import path churn** — every file that imports `LlmClient` or `costUsdForUsage` changes paths. Mitigation: centralised exports in `cli/refine/llm.ts` stay as a compatibility re-export, so callers need zero change.
- **Pricing drift between provider and adapter** — if Anthropic changes pricing, the table in llm-anthropic goes stale. Mitigation: annual audit + a CHANGELOG entry per provider-pricing change. Not automated.
- **Consumer pins a pre-0.8 CLI + a post-0.8 llm-anthropic** — shouldn't happen via `slowcook init` (it pins both together), but a hand-pin could cross versions. Mitigation: version-peer ranges (`@slowcook-ai/llm-anthropic@workspace:^` resolves to a floor, so a CLI update bumps both).

## Why 0.8 (not 1.0)

Package split with no behaviour change is a minor bump. `0.x.x` line is still "additive + bugfix"; the refactor doesn't break anyone using the CLI through its public commands. Semver major waits for an actually-breaking public surface change.
