## Goal

A zero-config overlay that turns any preview build of a mockup into a reviewable surface where the PM can leave **element-anchored comments** by clicking (desktop) or tapping (mobile) the element in question. Comments flow back to the refine PR as structured data the agent can act on without vision guessing.

No browser extension required. Opt-in via a single env var. Zero cost when off.

## Core UX commitment — modal toggle

Two modes:

1. **Test mode (default)** — all interactions behave normally. PM clicks buttons, fills forms, navigates. Toggle button floats top-right (desktop) / bottom-right (mobile).
2. **Review mode** — entered by pressing the toggle. Subtle red-orange tint overlays the viewport; cursor becomes a crosshair (desktop). All click/tap events are captured via `{ capture: true, preventDefault }` — no interaction fires. Hover highlights elements; click opens a comment sidebar for that element. Exit via the toggle, `Escape`, or (mobile) swipe-down on the sheet.

**Why not gestures.** Ctrl+click, right-click, long-press, two-finger tap all conflict with either browser UI (open-in-new-tab, context menu) or OS-level gestures (iOS text selection, Android context menus). A modal is discoverable, unambiguous, cross-platform, mistake-proof. See `0.12-mockup-first-refinement.md` §Review UX for the fuller reasoning.

### Desktop review mode

- Toggle button top-right, 40×40 px, `💬 Review` icon, coral background
- Pressed state: red-orange tint over viewport (`rgba(255, 107, 107, 0.05)` + 1px coral border flash)
- Cursor: `crosshair`
- Hover: element gets a coral outline (`2px solid coral, outline-offset: -2px`)
- Click: opens right-side sidebar (320px, slides in)
- Sidebar shows: selector preview, mini-screenshot of element, viewport info, existing comments on this element (if any), textarea for new comment, `Submit` button
- `Escape` → exits review mode
- `R` anywhere → toggles review mode (power-user shortcut)

### Mobile review mode

- Toggle button bottom-right, 48×48 px, same coral. Thumb-reachable.
- Pressed state: same red-orange tint, weaker on small screens
- Cursor: no-op (touch)
- Tap element: element outlined, bottom sheet slides up (40% viewport height, swipe-down dismisses)
- Sheet shows: selector, mini-screenshot, textarea, `Submit` button
- Tap outside sheet to dismiss without submitting
- No keyboard shortcuts (touch-only)

### Comment threading

Each element accumulates a thread:

```
┌──────────────────────────────────────────┐
│  Comments (2 open, 3 resolved)           │
├──────────────────────────────────────────┤
│  📍 .unread-badge · mobile-dark           │
│  PM: "Green badge should be coral"       │
│  └── Agent: "Fixed → bg-coral (abc123)"  │
│  [ Mark resolved ] [ Re-open ]           │
├──────────────────────────────────────────┤
│  📍 .save-button · desktop-light          │
│  PM: "Padding feels cramped vertically"  │
│  (open — awaiting agent)                 │
└──────────────────────────────────────────┘
```

Click a comment row → scrolls to + re-highlights that element. Resolved threads collapse.

## Data model

Each comment submit produces a structured payload:

```json
{
  "slowcook_overlay_version": "0.12.1",
  "story_id": "042",
  "element": {
    "selector": "#unread-badge",
    "fallback_selector": "span.badge.bg-mint:nth-child(2)",
    "tag": "span",
    "text_hint": "3",
    "file_hint": "src/components/notifications/NotificationBadge.tsx:14"
  },
  "viewport": {
    "name": "mobile-dark",
    "width": 390,
    "height": 844,
    "scheme": "dark"
  },
  "screenshot_png_base64": "...",
  "element_bounding_box": { "x": 142, "y": 73, "w": 22, "h": 22 },
  "coords_on_screenshot": { "x": 153, "y": 84 },
  "prose": "This is green. Should be coral — we use mint for success, not counts.",
  "timestamp": "2026-04-24T01:05:00Z",
  "browser": "chrome 132 on macOS 14.5"
}
```

Stable-selector extraction strategy (priority order):

1. `id` attribute (`#unread-badge`) — most stable
2. `data-testid` attribute (`[data-testid="unread-badge"]`)
3. `role` + accessible-name (`button[aria-label="Sign in"]`)
4. `tag.first-two-classes` with structural position (`span.badge.bg-mint:nth-child(2)`)
5. XPath — absolute, ugly, used only as last-resort fallback

`file_hint` is a best-effort: walk up the React Fiber tree (only available in dev builds) to find the component owner; use its `__reactFiber$*.debugOwner.fileName` property. Heuristic; not reliable in production minified builds. Skip if ambiguous.

## GitHub integration

Two mount modes for submission:

### Mode A — consumer's GitHub PAT (self-hosted)

PM installs a one-time `~/.slowcook-overlay-token` (PAT with `public_repo` or `repo` scope) OR the overlay prompts on first use ("To submit comments, paste a GitHub PAT with PR comment scope"). Stored in localStorage for the preview domain. Submit POSTs directly from the browser to GitHub's API:

```
POST /repos/{owner}/{repo}/issues/{pr_number}/comments
Body: markdown-rendered comment body + hidden HTML-comment JSON payload
```

The hidden JSON lets the refine agent parse the structured data back out; the rendered markdown is what humans see in the PR thread.

Comment body format:

```markdown
### Review comment — `#unread-badge` on mobile-dark

![screenshot](data:image/png;base64,...)

**PM:** This is green. Should be coral — we use mint for success, not counts.

<!--
slowcook:review-overlay
{"slowcook_overlay_version":"0.12.1","story_id":"042","element":{...},...}
-->
```

### Mode B — consumer's own submit endpoint (managed)

Consumer sets `SLOWCOOK_OVERLAY_SUBMIT_URL=https://api.reworthy.app/slowcook/review` in preview builds. Overlay POSTs to that URL; consumer's backend forwards to GitHub with a server-side token. Safer (no client token), more infra.

Mode A is the default for self-served previews; Mode B is the drop-in for orgs that don't want PATs in localStorage.

## React adapter — mount shape

```tsx
// src/app/layout.tsx
import { SlowcookReviewOverlay } from "@slowcook-ai/review-overlay/react";

export default function RootLayout({ children }) {
  return (
    <html>
      <body>
        {children}
        <SlowcookReviewOverlay
          // Only renders in review-enabled builds. No bundle cost otherwise.
          enabled={process.env.NEXT_PUBLIC_SLOWCOOK_REVIEW === "1"}
          storyId={process.env.NEXT_PUBLIC_SLOWCOOK_STORY_ID}
          prNumber={process.env.NEXT_PUBLIC_SLOWCOOK_PR_NUMBER}
        />
      </body>
    </html>
  );
}
```

Preview deploy workflow sets those three env vars from the PR context. Production never sets `NEXT_PUBLIC_SLOWCOOK_REVIEW=1`, so the overlay bundle is tree-shaken out.

## Framework-agnostic core

The package splits:

- `@slowcook-ai/review-overlay/core` — framework-free: event capture, selector extraction, screenshot (via html2canvas), sidebar UI in vanilla DOM, GitHub submit
- `@slowcook-ai/review-overlay/react` — React adapter (the exported component above)
- `@slowcook-ai/review-overlay/vue` — Vue adapter (post-1.0; not first-class in slowcook's stack-ts focus)

Core is the important part; React is a thin mount. Other adapters are possible but not promised.

## Existing-comments round-trip

On page load, the overlay fetches existing comments on the current PR:

```
GET /repos/{owner}/{repo}/issues/{pr_number}/comments
→ filter for comments containing the `slowcook:review-overlay` marker
→ parse each JSON payload
→ for each, find the element via selector → outline it with a persistent coral dot
```

Click a marker dot → opens the thread for that element. Respond → posts a reply comment referencing the original.

Resolved state lives in GitHub as a reaction (`✅` on the comment) or as a marker in a reply (`<!-- slowcook:resolved -->`). Overlay reads both.

## Bundle size target

- `/core`: <25 KB gzipped (excluding html2canvas which is ~50 KB — consumer can tree-shake if screenshots aren't needed)
- `/react`: <5 KB gzipped on top of core
- Lazy-load html2canvas on first review-mode activation (fetch when user presses the toggle, not on page load)

Preview builds only. Production bundle = 0 bytes. The env-gated import guarantees it.

## Out of scope for 0.12.1

- **Session recording / playback** (rrweb-style) — interesting but deferred; annotated comments go a long way first
- **Live multiplayer cursor / co-presence** — PM and agent seeing each other's cursors in real-time. Cool; far too much infra for MVP
- **Figma file embedding** — the overlay doesn't try to replace Figma. If the consumer has a Figma reference, it lives in the spec YAML as a URL
- **Pixel-perfect visual diff** — if PM wants "before vs after" visualization on the overlay, that's a post-1.0 enhancement. For now: Playwright's existing screenshot matrix does this job via CI, not the overlay
- **Non-web apps** — RN, Flutter, SwiftUI, etc. Out of scope; slowcook is web-first

## Validation

Dogfood on rewo:

1. Wire overlay into rewo's root layout with the env gates
2. Configure `NEXT_PUBLIC_SLOWCOOK_REVIEW=1` in Cloudflare Pages PR deploys (so previews activate the overlay; production stays clean)
3. Open a test PR that ships a deliberate visual issue
4. Use the overlay to leave a comment; verify:
   - Comment lands in the PR thread with rendered markdown + screenshot
   - Hidden JSON payload parses back to the same element info
   - Resolved state syncs between overlay UI and PR reaction
5. Tier-2 acceptance test that loads the preview, activates the overlay, leaves a stub comment, verifies it lands in GitHub via API

## Cost estimate

- **Implementation**: 2-3 days focused. The UX details dominate (mobile sheet behavior, keyboard shortcuts, screenshot reliability across Chromium/Firefox/Safari).
- **Overlay runtime cost**: near zero (event listeners, no polling). Bundle size as documented above.
- **Per-submit cost**: 1 GitHub API call (free). No LLM inference until refine picks up the structured comment.

## Related — brownfield extraction

Overlay doesn't depend on brownfield extraction, but they reinforce each other. Comments carry `file_hint` when dev-build React Fiber walk succeeds — but on a brownfield repo with many components, the agent needs the components-catalog from `slowcook map --emit-components-catalog` (see 0.12 §Brownfield extraction) to cross-reference which file the selector maps to. Without the catalog, the agent falls back to regex search. With it, the mapping is direct.

So the overlay ships a richer experience on brownfield consumers who've run `slowcook bootstrap` or `slowcook map --emit-*`. Works fine without; better with.
