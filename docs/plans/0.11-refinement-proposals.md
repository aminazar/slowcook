# 0.11 — Refinement proposals

> Status: drafted 2026-04-24. Prerequisite for 0.12 (mockup-first refinement). Implementation next release cycle.

## Why

Current refine translates an issue to a spec YAML. Greenfield stories frequently have gaps the issue author didn't fill in:

- Backend: ERD / migration SQL
- Frontend: design tokens, layout, component reuse
- Routes: page path + file location
- Auth: viewer requirements, RLS
- Perf: latency budget, scale expectation
- Observability: logs, metrics
- DevOps / infra: deploy target, runtime

A human developer detects these gaps and proposes defaults (or asks). Refine agent should too.

Brownfield projects have most of these in extant code/config — brew can read. Greenfield starts from empty; refine fills the void.

## Scope — `proposals:` block in spec YAML

### Schema change

Spec YAML gains an optional `proposals:` block. Each category is typed:

```yaml
story_id: "042"
title: "Notifications for new reactions on your rewos"
# ... existing fields unchanged ...

proposals:
  schema:
    status: pending  # pending | approved | rejected | deferred
    proposed_by: refine-agent
    rationale: "Story implies persistence; no notifications table exists."
    sql: |
      create table notifications (
        id uuid primary key default gen_random_uuid(),
        recipient_id uuid not null references profiles(id) on delete cascade,
        actor_id uuid not null references profiles(id) on delete cascade,
        rewo_id uuid not null references rewos(id) on delete cascade,
        emotion text not null,
        read_at timestamptz,
        created_at timestamptz default now()
      );
      create index on notifications (recipient_id, created_at desc);

  ui_layout:
    status: pending
    proposed_by: refine-agent
    viewport_coverage: [desktop-light, mobile-light, mobile-dark]
    components_to_reuse:
      - src/components/ui/nav-link.tsx
    tokens_to_reuse: [bg-card-bg, text-foreground/60, divide-card-border, text-coral]
    tokens_to_add: []

  routes:
    status: pending
    proposed_by: refine-agent
    paths:
      - path: /notifications
        file: src/app/(main)/notifications/page.tsx

  auth:
    status: pending
    proposed_by: refine-agent
    rationale: "Notifications are private per-viewer."
    requirements:
      - "Viewer must be authenticated"
      - "RLS: recipient_id = auth.uid()"

  perf_budget:
    status: deferred
    proposed_by: refine-agent
    rationale: "Initial list ≤ 50 items; scale not a concern yet."

  observability:
    status: pending
    proposed_by: refine-agent
    log_events:
      - notification.created
      - notification.read
    metrics:
      - name: notifications_unread_count
        type: gauge

  infra:
    status: deferred
    proposed_by: refine-agent
    rationale: "Fits existing Next + Supabase stack; no new deploy targets."
```

Fields: `status` (required, enum), `proposed_by` (required), `rationale` (optional prose), category-specific shape.

On approval, `approved_by` + `approved_at` are added; further agent updates must explicitly invalidate approval.

### PR body rendering

Spec PR body gets a "Proposals" section with:

- **Schema**: Mermaid `erDiagram` rendered from the `sql:` block (parse DDL → entities + FKs). Review by entity name.
- **UI layout**: bullet list of tokens + component reuse.
- **Routes**: table of path → file.
- **Auth, perf, observability, infra**: prose with rationale.

GitHub renders Mermaid natively in PR bodies — no external tool needed.

### Detect-or-ask rubric

Refine prompt extended with a heuristic:

For each of the 8 categories:

1. **Propose** if project context (context.md + existing code) gives enough grounding to pick a defensible default.
2. **Ask** (clarifying question) if proposing would be speculation.
3. **Defer** if the gap doesn't matter for this story (small read-only endpoint doesn't need perf budget).

Status reflects the choice: pending (proposed, awaiting approval) / deferred (skipped with reason) / blocked_on_clarification (ask mode).

## Non-goals for 0.11.0

- **`/refine` resubmit command + workflow** — deferred to 0.11.1. The initial release ships the proposal output; iteration on that output stays at the level of editing the spec PR manually. Automated `/refine` iteration needs the on-comment workflow + branch force-push + approval invalidation logic — bigger scope.
- **Brew reading proposals for allowed-paths** — deferred. Brew today already allows `supabase/migrations/**` (since 0.7.17); it doesn't strictly NEED to read the proposals block to close schema assertions.
- **Mockup generation** — that's 0.12.

## Implementation shape

### Changes to existing files

- `packages/cli/src/commands/refine/spec-yaml.ts` — `SpecSchema` gains optional `proposals` object with category shapes. Non-breaking: existing specs without `proposals` keep working.
- `packages/core/src/spec.ts` — `Spec` interface gains `proposals?: SpecProposals`.
- `packages/cli/src/commands/refine/prompts.ts` — `REFINE_SYSTEM` prompt grows a dedicated section per category: "When the story implies X and project context lacks Y, emit proposal Z."
- `packages/cli/src/commands/refine/agent.ts` — `renderSpecPrBody` (or whatever renders the PR body today) adds a "## Proposals" section with Mermaid for schema proposals + prose for others.
- **New**: `packages/cli/src/commands/refine/mermaid.ts` — parse DDL → Mermaid ERD. Simple regex-based; no full SQL parser.
- `packages/cli/src/commands/refine/prompts.ts` test file — snapshot tests for prompt stability.

### Version bumps

- `@slowcook-ai/core` 0.8.0 → 0.11.0 (schema addition; major-ish within 0.x)
- `@slowcook-ai/cli` 0.9.1 → 0.11.0 (prompt + renderer)

No changes to stack-ts, forge-github, llm-anthropic, recorder, gates.

## Validation

Dogfood on rewo by filing a greenfield issue like "add a notifications feed" with deliberately under-specified content. Expect:

1. Refine opens a spec PR with populated `proposals:` block
2. PR body renders Mermaid ERD of the proposed schema
3. Human reviews + approves some / edits others
4. (Stretch for 0.11.1:) reply `/refine` with corrections → agent amends on branch

## Cost impact

Refine LLM cost today: ~$0.30/spec. With proposals section: estimate $0.60-$1.00/spec (more generation, grounded in more context). Marginal — doesn't change the economics.

## Target timeline

~1 day of focused implementation + 1 refinement cycle against a real issue to tune the prompt. Ships as 0.11.0 in the next planned release window.
