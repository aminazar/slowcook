# slowcook 0.13.0 — Bug-fix flow + chef orchestrator + recipe rename

> **Status: shipped (cut 2026-04-25).** All 6 alphas (α.1 → α.5c) + α.3b LLM regression-test emitter landed; 345 tests green / 26 files. Successor: `0.14-mockup-first-refinement.md`.
> Pairs with: [`0.14-mockup-first-refinement.md`](./0.14-mockup-first-refinement.md) (deferred, not blocked by this).
> Predecessors: `0.7-testgen-two-tier.md` (the recipe step's existing model), `0.11-brownfield-retrieval.md` (Phase 2 retrieval ships in 0.12.x).

## Why

Through 0.12.x slowcook has shipped one pipeline shape: refine → testgen → brew. That shape is feature-shaped — refine asks design questions, testgen emits acceptance tests, brew implements. Bugs route through that pipeline awkwardly:

- Refine's clarifying-questions cycle is wrong shape for "X is broken; fix it." A bug usually has no design ambiguity, only a failure locus to find.
- Testgen's acceptance-test mode is wrong shape for "make this regression go green and never recur." A bug needs a regression test, not a multi-scenario acceptance suite.
- Brew's exploratory ratchet over-explores when the fix is a one-line change.

Three observed instances on rewo (2026-04-25) where bug-shaped issues sat awkwardly:

- `profiles.banned_at` missing migration — code reference present, no DDL. One-line fix; refine round-trip would produce a 60-line spec for a 2-line migration.
- `/api/discover` queries `rewos.user_id` (column never existed; `author_id` is what's there). Pure rename.
- `/feed` regression — _this one_ is genuinely story-shaped: it needs design decisions about RewoCard reuse, attribution shape, link target. Different beast.

Slowcook needs a parallel pipeline for bugs and a way to tell them apart. Plus, several PRs in this same period stalled silently when they hit conflicts or pre-existing-red CI gates — no agent owned the failure. We need an orchestrator.

## What ships in 0.13.0

| New | Purpose |
|---|---|
| `investigate` agent + command | Bug-flow analogue of refine. Reads code to find failure locus. Emits `bug-profile.yaml`. |
| `recipe --regression` mode | Bug-flow analogue of testgen acceptance mode. Emits a single failing test under `tests/regression/`. |
| `sift` agent + command | Bug-flow analogue of brew. Narrow-scoped, low-budget, regression-test-driven. |
| `chef` agent + command | Pipeline orchestrator. Watches all slowcook-bot PRs and recovers from failures (rebase / retry-dispatch / escalate). |
| `bug-profile.schema.json` | Schema for the investigate output. |

| Renamed | Reason |
|---|---|
| `testgen` → `recipe` | Strengthens the kitchen metaphor; aligns with chef + brew naming register. Keeps `testgen` as a hidden alias for one minor version so existing rewo workflow YAMLs don't break. |

| Existing, gains a `--retry` mode | Retry-on-failure is dispatched by chef; each agent must accept a `--retry` flag that loads context from the prior failed run. |
|---|---|
| refine | Re-emit spec with PM's latest comments folded in. |
| recipe (formerly testgen) | Re-emit tests after a brew/sift halt or after spec changes. |

                 │                                   │    chef     │

                 │                                   │  all PRs,   │

                 │  ┌──────────┐  ┌───────────────┐  ┌──────┐ │
   issue ───────►├─►│investigate├─►│recipe         │─►│ sift ├─┤
   ("bug")       │  │           │  │--regression   │  │      │ │

Story flow and bug flow are parallel; both emit PRs that chef watches. The brew/sift step uses the same red→green ratchet engine; the rest of the column has different shape per flow.

## Agents in detail

### `investigate` — find what's broken and where

- **Trigger:** issue with `bug` label opens, OR a comment containing `/investigate` posted by the issue author.
- **Inputs:** issue body + recent comments.
- **Tools:** `read_file`, `outline_file`, `find_references`, `find_definition`, `grep`, `list_directory`. NOT `write_file` — investigate doesn't propose code, only diagnoses.
- **Posture:** code-reading detective. Default zero rounds of clarifying questions; ask only if the symptom in the issue body is genuinely ambiguous (no concrete failure to find without more info).
- **Output:** `.brewing/bug-profiles/B-<id>.yaml` containing:
  - `bug_id` (auto-incremented; reuses spec-id race-fix from slowcook#8)
  - `source_issue` (#NNN)
  - `symptom` (the user-observable failure, paraphrased from issue body)
  - `expected` (the correct behavior)
  - `reproduction` (minimum steps; from issue or inferred)
  - `failure_locus` (file, line, function, diagnosis — the agent's findings)
  - `regression_assertion` (English-form: "Given X, when Y, then Z")
  - `fix_scope` (paths the regression-fix should touch, narrow)
  - `allowed_paths` (subset of repo, fed to sift)
  - `related_specs` (existing stories this bug touches)
- **PR shape:** opens `slowcook/bug-profile/B-<id>` branch with the YAML. Auto-merge gated on label transitioning from `bug` → `bug-profiled`.
- **Cost target:** $0.05–$0.20 (one round of code reads, no LLM round-trips for clarification in the typical case).

### `recipe` — emit tests (or regression)

- **Default mode:** unchanged from current testgen. Reads spec.yaml, emits tier-1 acceptance tests under `tests/integration/story-N-*.test.ts` plus any helpers / stubs / page-link / styling / column-presence assertions.
- **`--regression` mode:** reads `bug-profile.yaml`, emits a single test file under `tests/regression/B-<id>-<slug>.test.ts` that:
  - Sets up the exact failure-mode the profile names.
  - Asserts the corrected behavior.
  - Is initially **red** (the bug exists; regression test catches it).
  - Becomes green once sift fixes the code.
  - Stays in `tests/regression/` permanently — every future PR runs it, blocking re-introduction.
- **Implementation:** new `--mode=regression` flag on the existing `slowcook recipe` command. Reuses prompt-construction layers, swaps the test-template module.
- **Cost target:** $0.10–$0.30 (smaller than acceptance generation; one test, one fixture).

### `sift` — narrow red→green for bugs

- **Trigger:** regression test PR (from `recipe --regression`) merges, OR `bug-profiled` label transitions to `bug-recipe-merged`.
- **Inputs:** bug-profile.yaml + the regression test contents.
- **Engine:** shares the iteration loop with brew (red→green ratchet, snapshot-revert, manifest-driven test selection). Differences:
  - System prompt: "the regression test IS the contract; the bug profile names the failure locus; touch the named file and nothing else; if the fix needs more, halt voluntarily."
  - Default budget: $0.10–$0.50 (vs brew's $1–$3).
  - Default max iterations: 3 (vs brew's 10).
  - Default `allowed_paths`: from `bug-profile.fix_scope`, narrower than typical brew scope.
  - Voluntary-halt threshold: 1 zero-edit iteration triggers halt (vs brew's 2). Bug fixes that aren't trivial usually mean the bug-profile is wrong; cheaper to halt and let chef escalate than to keep iterating.
- **PR shape:** opens `slowcook/sift/B-<id>` branch. Auto-merge same as brew once green.
- **Cost target:** $0.10–$0.50 typical.

### `chef` — pipeline orchestrator

- **Trigger:** GitHub workflow listening to:
  - `pull_request.synchronize` on slowcook-bot PRs (head ref starts with `slowcook/`)
  - `check_suite.completed` with conclusion ≠ success on slowcook-bot PRs
  - `pull_request.labeled` with sentinel labels (`override-freeze`, `chef:retry`, `chef:no-retry`)
- **Reads:**
  - PR diff
  - CI run on PR head + CI run on merge base (used for self-vs-external classification)
  - Comment history (avoid retry-loop)
  - Labels (sift-no-retry, override-freeze, chef:escalate sentinel)
- **Classifies failures:**
  - **Self-conflict:** rebase. Auto-resolve append-only files (`specs/_index.yaml`, `.brewing/manifests/*.json`, gitignore section). Halt with diagnostic comment if conflict is in spec body or code body.
  - **Self-CI-fail:** failure new on PR head, not on base. Dispatch retry to originating agent's workflow with `--retry` flag. Cap 3 retries.
  - **External-CI-fail:** failure exists identically on merge base. Don't iterate — comment with diagnosis + link to base run + ask operator to admin-merge or fix the underlying.
  - **Infra-fail:** workflow infra error, OOM, npm registry hiccup. Re-run the workflow once; if still failing, comment + escalate.
- **Loop protection:** count chef-bot comments on the PR; after 3, refuse to iterate further regardless of class.
- **Workflow:** `slowcook-chef.yml`. Calls `slowcook chef --pr <num>` which runs the classification + dispatch.
- **Cost target:** $0 most invocations (rebase + workflow_dispatch require no LLM). LLM cost only when chef itself needs to summarize an unfamiliar failure for the escalation comment — rare path.

### `chef` — future scope (NOT 0.13.0)

These are explicitly deferred — they're listed so the v1 architecture doesn't preclude them:

- **PR review.** Chef runs ultrareview-style multi-perspective review on slowcook-bot PRs before they auto-merge. Replaces the manual "look at the diff" step.
- **Queue management.** When story-013 brews depend on story-012 merging first, chef enforces the order. Today: race conditions on parallel pipelines.
- **Cross-PR coordination.** Two stories touching the same file → chef serializes. No overlap → parallelize.
- **Cost gate.** Chef refuses to dispatch retries that would push spend over a configured budget without explicit human approval.

## Schema additions

### `bug-profile.schema.json`

```yaml
$schema: https://json-schema.org/draft/2020-12/schema
title: SlowcookBugProfile
type: object
required: [bug_id, source_issue, symptom, expected, failure_locus, regression_assertion, fix_scope]
properties:
  bug_id:           { type: string, pattern: "^B-[0-9]+$" }
  source_issue:     { type: string, pattern: "^#[0-9]+$" }
  status:           { type: string, enum: [investigated, recipe-emitted, sifted, shipped, closed] }
  symptom:          { type: array, items: { type: string } }
  expected:         { type: array, items: { type: string } }
  reproduction:     { type: array, items: { type: string } }
  failure_locus:
    type: object
    properties:
      file:         { type: string }
      line:         { type: integer }
      function:     { type: string }
      diagnosis:    { type: string }
  regression_assertion: { type: array, items: { type: string } }
  fix_scope:        { type: array, items: { type: string } }
  allowed_paths:    { type: array, items: { type: string } }
  related_specs:
    type: array
    items:
      type: object
      properties:
        id:           { type: string }
        relationship: { type: string, enum: [touches, supersedes, related] }
```

## Workflow additions

| File | Trigger | Purpose |
|---|---|---|
| `.github/workflows/slowcook-investigate.yml` | issue `opened`/`labeled` with `bug` | Run `slowcook investigate <issue#>` → bug-profile PR |
| `.github/workflows/slowcook-sift.yml` | pull_request `closed:merged` with head ref `slowcook/recipe-regression/*` | Run `slowcook sift <bug-id>` |
| `.github/workflows/slowcook-chef.yml` | check_suite `completed` failure on `slowcook/*` head refs OR pull_request `synchronize` | Run `slowcook chef --pr <num>` |

Existing workflows (`slowcook-refine.yml`, `slowcook-testgen.yml` → `slowcook-recipe.yml`, `slowcook-brew.yml`) get `workflow_dispatch` triggers for chef-driven retries. Each accepts a `pr-number` input that the agent reads to load failure context.

## Backwards compatibility

- `slowcook testgen` keeps working in 0.13.x — wired as a hidden alias of `slowcook recipe`. Removed in 0.14.0.
- The `testgen` workflow file gets renamed `recipe` but the old name is symlinked / aliased so existing rewo workflow files continue to fire. Documented as a single-version migration.
- `brew` is unchanged — same command, same flags, same defaults. Sift is additive.
- `bug-profile.yaml` is new — no existing consumers to break.
- Existing rewo `tests/integration/` and `tests/schema/` directories are untouched. New `tests/regression/` directory is a no-op until the first sift PR lands.

## Validation plan

The three rewo bugs filed 2026-04-25 (`#127` banned_at, `#128` discover, `#126` /feed regression — though that one's genuinely a story) form the dogfood validation set:

1. Once 0.13.0 ships, replay #127 + #128 through the bug flow (re-create as fresh issues OR use the originals if their fixes haven't merged yet — the `bug`-labeled audit trail is in place).
2. Compare against the hand-fix baseline (PR #130, ~5 minutes me-time, $0 spend).
3. Target: investigate + recipe + sift cumulative cost < $0.50 per bug; total chef intervention rate < 30% of bug PRs.

For the orchestrator (chef): the recurring `pending_brew_ci_gate` problem in rewo (every PR fails on pre-existing-red story-001 schema tests) is the inverse validation — chef should classify those as external on every PR and surface the comment, not retry.

## Open questions

- **Bug-id scheme** — `B-<n>` (parallel to `story-<NNN>`) vs reuse the issue number (`B-127`). Lean: `B-<n>` to keep numbering small + sequential. Slowcook#8 fix applies to both story-id and bug-id collision avoidance.
- **Where does `bug-profile.yaml` live?** Lean: `.brewing/bug-profiles/B-<id>.yaml`, parallel to `specs/story-<NNN>.yaml`. Keeps the audit-trail surface in one place.
- **Sift's halt-rationale comment** — when sift voluntarily halts, who picks it up? Today brew halts → operator looks. Sift halts on a bug → operator should usually edit the bug-profile (the locus was wrong) rather than retry blindly. Workflow comment should suggest that path.
