# 0.20-and-beyond decisions

> Resolves the five open questions raised in [`0.20-and-beyond.md`](./0.20-and-beyond.md). This doc is the **authoritative answer set**; the strategy doc remains the ideation/research record.

Date: 2026-05-27. Decided by: the maintainer (`@aminazar`).

## The five decisions

### 1. OSS-only vs OSS-core + commercial-layer?
**Both.** Slowcook OSS stays free + MIT. A separate commercial layer monetizes the team-platform features (PM tools, budget, multi-role gates, ledger, ops).

### 2. PM tool: Linear or Jira first?
**Linear.** Cleaner API + webhooks (≈3× development cost less than Jira), aligned with the AI-native-engineering-org segment slowcook targets, integrated by Devin / Cursor / Cline / Sweep — the trend signal is unambiguous. Jira is a fast-follow only if commercial customer demand surfaces it.

### 3. Should OSS gain "team" features (PM integration, budget, dashboards, ledger)?
**No.** OSS stays lean as the agent harness. Every team-platform feature lives in the commercial repo. This keeps the OSS surface tight + defensible (no temptation to half-build commercial features in OSS) and gives the commercial layer a clear value-add.

### 4. Outside contributors on OSS?
**Open it up.** Welcome community PRs + issues on `aminazar/slowcook`. This:
- Multiplies development velocity on agent-harness features
- Builds public adoption signal (one of the 1.0 criteria is 3+ external consumers)
- Creates a community to refer commercial customers from

The commercial repo (`slowcook-platform`, private) stays maintainer-controlled.

### 5. Where lives the commercial layer?
**Separate private repo under the slowcook brand.** Working name: `slowcook-platform` (final name TBD). Depends on `@slowcook-ai/*` packages from npm. The OSS↔commercial interface is the slowcook cli + `spec.schema.json` + the knowledge layer files in `.brewing/` — all stable surface as of 0.19.0.

## Community contribution stance (Q4 follow-through)

Concrete moves needed in OSS to actually invite contributors:

1. **CONTRIBUTING.md polish** — already exists; verify it covers branch convention + test gate + commit convention + how to run the agent locally
2. **`good first issue` label** — apply to known-small tasks; maintain ≥3 open at all times
3. **PR-review SLA** — public commitment: "PRs reviewed within 3 days; merge or actionable feedback within 7"
4. **`code-review` welcoming** — automated welcome bot on first-PR-from-new-contributor (Github action)
5. **Reachability** — discussion forum or Discord-style chat? Defer until contribution velocity warrants
6. **Public roadmap** — `docs/plans/` is already public; add a roadmap snapshot in README that always points at the current cut
