# 0.9 — Tier-2 acceptance runner + screenshot capture

> Status: drafted 2026-04-23. Implementation will ship in multiple point releases (0.9.0 lays the runner; 0.9.1+ adds recorder, scrubber, screenshot storage).
>
> Parent roadmap: `roadmap-0.7-to-0.11.md`. The roadmap originally paired this with the LLM adapter refactor under 0.8; after shipping 0.8 as pure-decoupling-only, tier-2 shifts here and gates (original 0.9) become 0.10.

## Why now

Three gaps have already been closed at tier-1 (page-integration 0.7.17, schema 0.7.18, styling 0.7.21). Tier-1 catches these at the source-file level via static scans. Tier-2 catches the FOURTH category: **does the feature work end-to-end against a real sandbox?** Mock drift, missing env var wiring, auth flows, migration application, storage buckets, edge functions — all things that pass in mocks and break in production.

Tier-2 is also where screenshots live. Prompt-only steering failed to produce styled components (demonstrated empirically in the 0.7.20 → 0.7.21 arc); screenshots + vision review close the last residual slack in "does it LOOK right."

## Scope — three tracks, each a point release

### 0.9.0 — Runner harness + first acceptance test (MVP)

Smallest useful slice. Consumer gets a `tests/acceptance/` directory, a `slowcook-acceptance.yml` workflow template, and the ability to author tests that hit a real Next.js dev server + real Supabase.

**Delivered:**
- **`stack-ts` extensions**: `discover.ts` recognises `tests/acceptance/`. `runs.ts` exposes an `acceptance` variant keyed on `ACCEPTANCE=1`. New `scripts.test:acceptance` added to the `slowcook init` package-json patch.
- **Playwright setup**: stack-ts scaffold emits `playwright.config.ts` + devDependency `@playwright/test`. First-time `slowcook init` runs `npx playwright install chromium` in a post-hook (or flags it clearly in the post-init message).
- **Sandbox spin-up helper**: new `tests/helpers/sandbox.ts` emits by `slowcook init`. Exposes `withSandbox(async ({baseUrl, supabase}) => {...})` that boots `next dev` on a random port + waits for readiness. Sandbox teardown is `afterAll`. Supabase connection uses the consumer's `.env.acceptance` (user provides; template emits a `.env.acceptance.example`).
- **`slowcook-acceptance.yml` workflow**: runs on `pull_request` (label-gated to `slowcook-brew` / `slowcook-tests`) + nightly cron. Installs deps, runs `ACCEPTANCE=1 npx playwright test tests/acceptance/`, uploads screenshots as artifact on failure.
- **First hand-authored test** for rewo story-005: visit `/u/<handle>`, assert the handle renders, assert the follow button shape matches the `followsAvailable:false` "Coming soon" behaviour.
- **Docs + context.md snippet** telling brew what tier-2 tests look like and when NOT to try to fix them (most brew halts on tier-2 should escalate; agents don't spin up sandboxes).

**Explicitly deferred** (see 0.9.1, 0.9.2):
- Recorder / replay. Acceptance tests in 0.9.0 hit live Supabase using hand-seeded data. Flaky by construction until 0.9.1 adds replay.
- Scrubber. Without recorder there's nothing to scrub.
- MinIO screenshot storage. 0.9.0 uploads screenshots as GitHub Actions artifacts (auto-expire in 30 days). 0.9.2 promotes to MinIO for retention.

### 0.9.1 — Recorder + scrubber + fixture-staleness gate

Record/replay turns flaky sandbox hits into deterministic fixtures. First recording populates `tests/fixtures/<story-id>/<service>/<request-hash>.json`; replay intercepts outbound calls and serves from disk.

**Delivered:**
- **Recorder**: wrapper around `@supabase/supabase-js` (first provider; pattern generalises) that intercepts every request → response pair. Mode switched by env: `SLOWCOOK_RECORD=1` (live + save), `SLOWCOOK_REPLAY=1` (offline + use cached), unset (raw — original behaviour).
- **Stable hash**: hash includes method + path + sorted query params + sorted body keys. Body-field order shouldn't cache-bust.
- **Scrubber**: pre-save pass replaces volatile fields (uuids, emails, bearer tokens, timestamps) with placeholders per a config in `@slowcook-ai/stack-ts` (defaults loud). CI refuses any PR where a fixture file contains a raw pattern matching leaked-secret regexes.
- **`slowcook fixtures check`** new CLI command: fails if newest fixture under `tests/fixtures/<story-id>/` is older than N days (default 14) unless spec has `@fixtures-frozen <reason>` marker.
- **First recorded test**: the 0.9.0 rewo story-005 acceptance test gains `SLOWCOOK_RECORD=1` on its first CI run, committing fixtures. Subsequent runs use `SLOWCOOK_REPLAY=1`.

### 0.9.2 — Screenshots + MinIO storage + artifact surfacing

Playwright screenshots per `(viewport × scheme)` during every acceptance run. Stored for gate consumption (0.10).

**Delivered:**
- **Viewport matrix**: desktop-light (1440×900 light), mobile-light (390×844 light), mobile-dark (390×844 with `prefers-color-scheme: dark`). Configurable per-story via `ui_behavior.<viewport-scheme>` — if the spec doesn't describe a viewport, skip it.
- **Capture helper** in `tests/helpers/screenshots.ts`: `await captureScreenshots(page, { story: "005", commit: "..." })` snaps all matrix entries, names them `story-005/<commit-sha>/<viewport>-<scheme>.png`.
- **MinIO store adapter** (`@slowcook-ai/storage-minio`? or inline in stack-ts first). Upload each screenshot keyed on `story-id × commit-sha × viewport × scheme`. Consumer provides `MINIO_*` env vars; scaffolded `.env.acceptance.example`.
- **Artifact fallback**: if no MinIO configured, upload as GHA artifact (already shipped in 0.9.0).
- **PR comment with thumbnails**: `slowcook-review[bot]` posts one comment per brew PR linking the full-size images. Mirrors 0.10's Gate 3 delivery path.

## Non-goals for 0.9

- **No Gate 1 / Gate 2 / Gate 3 logic** — that's 0.10. 0.9 just CAPTURES the inputs.
- **No testgen for acceptance tests** — deferred to 0.11 (testgen for tier-2 needs the recorder first; chicken-and-egg).
- **No cross-browser matrix** — chromium-only for 0.9. Firefox/WebKit when there's demand.
- **No visual diffing** — screenshots are stored for gate consumption; visual regression diff is a 0.11+ consideration.

## Consumer impact

`slowcook init` rerun on rewo adds:
- `tests/acceptance/` directory (empty)
- `tests/helpers/sandbox.ts`
- `playwright.config.ts`
- `.env.acceptance.example`
- `@playwright/test` devDep
- Updated `slowcook-acceptance.yml` workflow

Rewo must populate `.env.acceptance` with a real Supabase URL + anon key pointing at a staging project (NOT prod). That's ops work — not code.

## Risk register

- **Playwright install is ~300MB and slow**. Mitigation: the `slowcook init` post-hook warns about this explicitly; consumers can skip if they don't want tier-2.
- **Sandbox flakiness dominates until 0.9.1**. Expected; document in `context.md`. If a test is red-on-CI-green-on-local, look for non-deterministic fixtures first; raise as a record-target on next 0.9.1 dogfood.
- **Brew tries to fix tier-2 tests by editing them**. Mitigation: `tests/acceptance/` added to `.brewing/frozen-paths.json` (same treatment as `tests/integration/`). Brew's prompt already says "never edit tests/" but making it frozen is the hard guard.
- **Staging Supabase leaks into prod via a misconfigured env var.** Mitigation: `.env.acceptance.example` checks in with obvious placeholder values; the scrubber's secret-leak regex ensures nothing real lands in committed fixtures.

## Validation

Done when rewo story-005 has:
1. A passing `tests/acceptance/story-005.spec.ts` running on every brew PR.
2. Committed fixtures under `tests/fixtures/story-005/supabase/`.
3. At least one screenshot per (viewport × scheme) captured + attached to the PR.
4. `slowcook fixtures check` running in CI + green.

Grand total implementation: ~15-25 hours across three point releases (0.9.0 smallest, 0.9.1 largest with the recorder).

## Interaction with 0.10 (gates)

0.9 captures screenshots; 0.10 grades them. They're decoupled so 0.9 can ship (and be used manually by the PM to review) without waiting for Gate 1/2/3 implementation.
