# 0.17 — Branding & logo distribution

> Status: drafted 2026-05-03. Defer until current 0.16 dogfood arc completes (`brew --mode plate` validated end-to-end on rewo). Branding is polish; pipeline correctness comes first.

## Context

The slowcook logo (slow-cook pot + steam wisps + lid + side handles) is currently inline-SVG-only inside two React components — the review pill (`@slowcook-ai/review-overlay/src/react/overlay.tsx`) and the ScenarioPicker brand mark (`@slowcook-ai/mock-runtime/src/scenario-picker.tsx`). Two copies, kept in sync by hand.

There's no other surface using it: npm pages show the default scope avatar, GitHub repo card shows your user avatar, no social-preview image, no favicon on the mock app, no README hero on any package.

## Goals

1. Single canonical asset; React components import or inline from one source.
2. Logo visible on npm package pages (via README hero + scope avatar).
3. Logo visible on GitHub: repo social-preview image, README hero, optional org profile.
4. Logo as the mock app's favicon (so the browser tab carries the slowcook brand).
5. No regressions in bundle size — the SVG is already ~600 bytes; lifting to a shared asset shouldn't bloat anything.

## Surfaces + recommended action

| Surface | Recommended | Notes |
|---|---|---|
| npm scope avatar (`@slowcook-ai`) | Upload PNG via npmjs.com org settings | Shows on every package page's icon. Recommended 120×120 PNG. |
| npm package page hero | `<picture>` block at top of each package README | Need light + dark SVG sources. GitHub renders the same README from npm's CDN. |
| GitHub repo social-preview | Settings → Options → Social preview → PNG | 1280×640. Used in Slack / Twitter unfurls. |
| GitHub README hero | `<p align="center"><picture>...</picture></p>` | Top of root README + each package's README. |
| GitHub org profile (optional) | Create `slowcook-ai/.github` repo with `profile/README.md` | Only if we re-home the project under an org (see "open question" below). |
| Mock app favicon | Add `mock/public/favicon.ico` + `favicon.svg` to the `slowcook init mock` template | Browser-tab branding. |
| Mock app PWA manifest | Optional `manifest.webmanifest` with 192/512 PNG icons | If a future "install as app" affordance lands. |

## Open question — GitHub org

The npm scope `@slowcook-ai` exists; the GitHub repo `aminazar/slowcook` is under your **user** profile. Two options:

1. **Stay user-owned**, ship the brand only via per-repo surfaces (social preview, README hero). Cheap; PRs / URLs unchanged.
2. **Re-home under a new `slowcook-ai` GitHub org**. Cleaner brand surface (org avatar everywhere), aligns with the npm scope. Cost: PR + issue URLs redirect (GitHub does this automatically), CI secrets need re-creation in the org, contributors notice the move once.

Recommend **option 1 first** (do everything in #1 below), revisit option 2 only if external contributors / press attention surfaces a need.

## Implementation (when picked up)

### Phase A — extract logo asset (~1h)

1. Create `assets/logo.svg` (single source, uses `currentColor`).
2. Create `assets/logo-light.svg` + `assets/logo-dark.svg` (explicit colors for GitHub README — `currentColor` doesn't theme-swap there).
3. Create `assets/wordmark.svg` (logo + "slowcook" text inline) for marketing surfaces.
4. Update overlay.tsx + scenario-picker.tsx to inline-import from a single TS module exporting the SVG string (or accept duplication for now and treat the two inlined copies as the runtime surface; assets/ is for documentation surfaces only).

### Phase B — generate raster outputs (~1h)

1. Add a `tools/build-logo-rasters.mjs` script using `sharp` or `svgexport`.
2. Output: `assets/logo-32.png`, `logo-192.png`, `logo-512.png`, `social-preview-1280x640.png`, `npm-avatar-120.png`.
3. Optional: GitHub Action `branding-rasters.yml` regenerates on `assets/*.svg` change.

### Phase C — wire surfaces (~1h)

1. **Root README** — `<p align="center">` with `<picture>` + light/dark sources at the very top.
2. **Each package README** (cli, review-overlay, mock-runtime, forge-github, llm-anthropic, core, gates, recorder, stack-ts) — same hero block. Most are seen on npm.
3. **`slowcook init mock` template** — bundle `mock/public/favicon.ico` + `favicon.svg` so consumers' mocks carry the brand.
4. **GitHub repo settings** — manually upload the social-preview PNG via Settings → Options. (Can't be automated without GH API token + script.)
5. **npm scope avatar** — manually upload via npmjs.com → Settings → `@slowcook-ai` → Avatar. (Same — manual one-time.)

### Phase D — optional (~2h)

1. **Re-home under `slowcook-ai` GitHub org** (only if option 2 above wins).
2. **Org profile README** at `slowcook-ai/.github` for the org landing page.

## Out of scope

- Brand color palette / typography system (the inline-SVG logo is enough for v0; a full brand system can wait).
- Marketing site (`slowcook.dev` or similar). Different doc; defer indefinitely.
- Animated logos / Lottie. The static SVG is sufficient.
